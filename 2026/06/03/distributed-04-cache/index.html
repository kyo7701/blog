分布式缓存：架构、问题与解决方案

2026-06-03 分布式 Redis, 一致性, 分布式, 缓存 0 Comments Word Count: 1.7k(words) Read Count: 5(minutes)

前言

缓存是提升系统性能的重要手段，但是当单机缓存无法满足需求时，我们就需要引入分布式缓存。分布式缓存虽然解决了容量和性能问题，但也带来了一系列新的挑战。今天就来聊聊分布式缓存的架构设计、常见问题以及解决方案

为什么需要分布式缓存

单机缓存的局限性

  1. 容量有限：单机内存有限，无法存储大量数据
  2. 性能瓶颈：单机处理能力有限，无法应对高并发
  3. 单点故障：单机宕机，缓存服务不可用
  4. 扩展性差：无法通过增加机器来提升性能

分布式缓存的优势

  1. 容量扩展：通过增加节点来扩展存储容量
  2. 性能提升：通过多节点并行处理来提升性能
  3. 高可用：通过集群和主从复制来保证可用性
  4. 负载均衡：将请求分散到多个节点

分布式缓存的架构

客户端路由

一致性哈希

  • 将缓存节点映射到哈希环上
  • 数据根据哈希值映射到对应的节点
  • 节点增减时，只有少量数据需要迁移

哈希取模

  • 数据根据哈希值对节点数取模
  • 实现简单
  • 节点增减时，大量数据需要迁移

代理层

  • 在客户端和缓存节点之间增加代理层
  • 代理负责路由和负载均衡
  • 代表：Twemproxy、Codis

集群模式

  • 缓存节点之间相互通信
  • 数据自动分片
  • 代表：Redis Cluster

缓存的常见问题

缓存穿透

什么是缓存穿透

查询一个一定不存在的数据，由于缓存未命中，每次都要查数据库，失去了缓存的意义

解决方案

  1. 缓存空值：将空结果也缓存起来
  2. 布隆过滤器：使用布隆过滤器判断数据是否存在
  3. 接口校验：在接口层进行参数校验

缓存击穿

什么是缓存击穿

某个热点key过期，大量请求同时打到数据库

解决方案

  1. 互斥锁：使用分布式锁，只允许一个请求重建缓存
  2. 永不过期：热点数据不设置过期时间
  3. 提前续期：在过期前异步更新缓存

缓存雪崩

什么是缓存雪崩

大量缓存同时过期，请求全部打到数据库

解决方案

  1. 随机过期时间：在过期时间上增加随机值
  2. 多级缓存：使用本地缓存+分布式缓存
  3. 限流降级：在缓存失效时进行限流

缓存一致性

什么是缓存一致性

缓存中的数据与数据库中的数据不一致

解决方案

Cache Aside Pattern

  • 读：先读缓存，缓存没有则读数据库，然后更新缓存
  • 写：先更新数据库，再删除缓存

Read/Write Through

  • 读写都通过缓存层
  • 缓存层负责与数据库同步

Write Behind

  • 写操作只更新缓存
  • 异步批量更新数据库

延迟双删

  1. 先删除缓存
  2. 更新数据库
  3. 延迟一段时间后再次删除缓存

监听binlog

  • 监听数据库的binlog
  • 根据binlog更新缓存

缓存的淘汰策略

常见策略

  1. LRU（Least Recently Used）：淘汰最近最少使用的数据
  2. LFU（Least Frequently Used）：淘汰使用频率最低的数据
  3. FIFO（First In First Out）：先进先出
  4. TTL（Time To Live）：根据过期时间淘汰

Redis的淘汰策略

  1. noeviction：不淘汰，内存满时返回错误
  2. allkeys-lru：在所有key中使用LRU
  3. volatile-lru：在设置了过期时间的key中使用LRU
  4. allkeys-random：在所有key中随机淘汰
  5. volatile-random：在设置了过期时间的key中随机淘汰
  6. volatile-ttl：淘汰TTL最小的key

缓存的高可用

主从复制

  • 主节点负责写操作
  • 从节点负责读操作
  • 数据异步复制

哨兵模式

  • 监控主从节点的健康状态
  • 主节点宕机时自动故障转移
  • 通知客户端新的主节点地址

集群模式

  • 数据自动分片
  • 节点之间互相通信
  • 支持动态扩缩容

缓存的监控

关键指标

  1. 命中率：缓存命中次数 / 总请求次数
  2. 内存使用率：已用内存 / 总内存
  3. 连接数：当前连接数
  4. QPS：每秒请求数
  5. 延迟：请求响应时间

监控工具

  1. Redis INFO：Redis自带的监控命令
  2. Redis Monitor：实时监控Redis命令
  3. Prometheus + Grafana：监控和可视化
  4. Redis Insight：Redis官方的监控工具

缓存的最佳实践

1. 合理设置过期时间

  • 热点数据可以设置较长的过期时间
  • 冷数据可以设置较短的过期时间
  • 避免大量数据同时过期

2. 使用合适的数据结构

  • String：简单的key-value
  • Hash：对象存储
  • List：列表数据
  • Set：去重数据
  • ZSet：有序数据

3. 避免大key

  • 大key会阻塞Redis
  • 拆分大key为多个小key
  • 使用压缩算法

4. 使用Pipeline

  • 批量操作使用Pipeline
  • 减少网络往返
  • 提升性能

5. 使用连接池

  • 使用连接池管理连接
  • 避免频繁创建和销毁连接
  • 设置合理的连接数

6. 序列化优化

  • 选择高效的序列化方式
  • 避免使用Java序列化
  • 推荐使用Protobuf、Kryo

多级缓存架构

本地缓存

  • 进程内缓存
  • 性能最高
  • 容量有限
  • 代表：Caffeine、Guava Cache

分布式缓存

  • 跨进程共享
  • 容量大
  • 性能相对较低
  • 代表：Redis、Memcached

多级缓存的读写流程

读流程

  1. 先读本地缓存
  2. 本地缓存没有，读分布式缓存
  3. 分布式缓存没有，读数据库
  4. 将结果写入缓存

写流程

  1. 更新数据库
  2. 删除分布式缓存
  3. 删除本地缓存（或等待过期）

总结

今天我们学习了分布式缓存的相关知识

  1. 分布式缓存的架构：客户端路由、代理层、集群模式
  2. 缓存的常见问题：穿透、击穿、雪崩、一致性
  3. 缓存的淘汰策略：LRU、LFU、FIFO、TTL
  4. 缓存的高可用：主从复制、哨兵模式、集群模式
  5. 缓存的最佳实践：合理设置过期时间、避免大key、使用Pipeline
  6. 多级缓存架构：本地缓存 + 分布式缓存

分布式缓存是提升系统性能的重要手段，合理使用缓存可以大大提升系统的吞吐量和响应速度
