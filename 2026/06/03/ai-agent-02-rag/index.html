聊聊AI Agent（二）：RAG检索增强生成

2026-06-03 AI Agent系列 AI, LLM, RAG, 向量数据库 0 Comments Word Count: 2.2k(words) Read Count: 7(minutes)

前言

在上一篇文章中，我们了解了Agent的基本概念。我们知道Agent需要使用工具来完成任务，而RAG（Retrieval-Augmented Generation，检索增强生成）就是Agent最重要的工具之一。今天就来聊聊RAG是什么，它是怎么工作的，以及它解决了什么问题

什么是RAG

RAG的全称是Retrieval-Augmented Generation，翻译过来就是”检索增强生成”。它是一种结合了检索（Retrieval）和生成（Generation）的技术

用通俗的话来说，RAG就是让大语言模型（LLM）在回答问题之前，先从外部知识库中检索相关信息，然后基于这些信息来生成回答

为什么需要RAG

那么为什么需要RAG呢？我们来看看LLM的几个问题

1. 知识截止日期

LLM的训练数据有一个截止日期，它不知道截止日期之后发生的事情

比如你问GPT-4：”2025年诺贝尔文学奖得主是谁？”

GPT-4可能会说”我不知道”或者给出错误的答案，因为它的训练数据截止到2024年

2. 幻觉问题

LLM有时候会”一本正经地胡说八道”，生成看似正确但实际错误的内容

这是因为LLM本质上是一个概率模型，它会根据上下文生成最可能的下一个词，而不是基于事实

3. 私有知识

LLM没有你公司的内部文档、你个人的笔记等私有知识

比如你问：”我们公司的请假流程是什么？”

LLM无法回答这个问题，因为它没有你公司的内部信息

4. 专业领域知识

LLM的训练数据可能不包含某些专业领域的最新知识

比如医学、法律、金融等领域的最新研究成果

RAG如何解决这些问题

RAG通过以下方式解决上述问题

基本流程

工作原理

  1. 用户提问：用户提出问题
  2. 检索相关文档：从知识库中检索与问题相关的文档
  3. 构建提示词：将检索到的文档和用户问题一起构建成提示词
  4. 生成回答：LLM基于检索到的文档生成回答

为什么这样能解决问题

  • 知识截止：通过检索最新的文档，获取最新信息
  • 幻觉问题：LLM基于检索到的事实生成回答，减少幻觉
  • 私有知识：将私有文档构建成知识库，LLM可以访问
  • 专业领域：将专业领域的文档构建成知识库

RAG的核心组件

一个完整的RAG系统包含以下几个核心组件

1. 文档加载器（Document Loader）

文档加载器负责将各种格式的文档加载到系统中

支持的文档格式：

  • 文本文件：TXT、Markdown
  • PDF文件：学术论文、技术文档
  • 网页：HTML页面
  • Office文档：Word、Excel、PPT
  • 数据库：结构化数据

2. 文本分割器（Text Splitter）

由于LLM的上下文窗口有限，我们需要将长文档分割成小块

为什么要分割文档？

  • LLM的上下文窗口有限，无法处理太长的文本
  • 小块的文本更容易检索到相关内容
  • 减少噪音信息，提高检索精度

常见的分割策略：

  • 固定长度分割：按字符数或token数分割
  • 语义分割：按段落、章节分割
  • 递归分割：先按大块分割，再按小块分割

3. 嵌入模型（Embedding Model）

嵌入模型负责将文本转换为向量，以便进行相似度计算

什么是向量？

向量就是一组数字，可以表示文本的语义信息。比如：

  • “猫”和”狗”的向量比较接近（都是宠物）
  • “猫”和”汽车”的向量距离较远（语义不同）

嵌入模型的作用：

  • 将文本转换为高维向量
  • 保留文本的语义信息
  • 支持相似度计算

4. 向量数据库（Vector Store）

向量数据库负责存储和检索向量

常见的向量数据库：

  • Chroma：轻量级，适合本地开发
  • FAISS：Facebook开源，性能优秀
  • Pinecone：云服务，易于扩展
  • Weaviate：开源，功能丰富
  • Milvus：开源，适合大规模部署

向量数据库的核心能力：

  • 向量存储：高效存储大量向量
  • 相似度检索：快速找到最相似的向量
  • 过滤：根据元数据过滤结果

5. 检索器（Retriever）

检索器负责从向量数据库中检索相关文档

常见的检索策略：

  • 相似度检索：根据向量相似度检索
  • 关键词检索：根据关键词匹配检索
  • 混合检索：结合相似度和关键词检索

6. 大语言模型（LLM）

LLM负责基于检索到的文档生成回答

LLM的作用：

  • 理解用户问题
  • 理解检索到的文档
  • 生成准确、连贯的回答

RAG的高级技巧

1. 查询转换

有时候用户的查询可能不太适合直接检索，我们可以通过LLM来转换查询

常见的查询转换方式：

  • 查询重写：将用户的口语化查询转换为标准查询
  • 查询扩展：生成多个相关查询，提高召回率
  • 查询分解：将复杂查询分解为多个简单查询

2. 混合检索

结合多种检索方式来提高召回率

  • 向量检索：基于语义相似度
  • 关键词检索：基于关键词匹配
  • 混合检索：结合两者的优势

3. 重排序

对检索结果进行重新排序，将最相关的文档放在前面

重排序的意义：

  • 初始检索可能不够准确
  • 重排序可以提高结果质量
  • 减少LLM处理的噪音信息

4. 多轮对话

支持多轮对话的RAG系统

需要解决的问题：

  • 如何理解上下文
  • 如何处理指代关系
  • 如何维护对话历史

RAG的评估

如何评估RAG系统的好坏？

1. 检索评估

评估检索到的文档是否相关

常用指标：

  • 召回率：检索到的相关文档占所有相关文档的比例
  • 精确率：检索到的文档中相关文档的比例
  • MRR（Mean Reciprocal Rank）：第一个相关文档的排名

2. 生成评估

评估生成的回答是否准确

常用指标：

  • 准确性：回答是否正确
  • 完整性：回答是否完整
  • 相关性：回答是否与问题相关
  • 忠实度：回答是否基于检索到的文档

RAG的架构演进

Naive RAG

最基本的RAG架构

问题：

  • 检索质量不稳定
  • 无法处理复杂查询
  • 缺乏上下文理解

Advanced RAG

改进的RAG架构

改进：

  • 查询转换提高检索质量
  • 重排序提高结果相关性
  • 更好的上下文处理

Modular RAG

模块化的RAG架构

特点：

  • 模块化设计
  • 灵活组合
  • 易于扩展

RAG的最佳实践

1. 文档质量

  • 确保文档的准确性和时效性
  • 定期更新知识库
  • 清理过期文档

2. 分块策略

  • 选择合适的分块大小
  • 保留足够的上下文
  • 避免信息碎片化

3. 检索优化

  • 选择合适的检索策略
  • 优化向量模型
  • 使用混合检索

4. 提示词工程

  • 设计清晰的提示词
  • 明确指示LLM基于检索结果回答
  • 处理”我不知道”的情况

总结

今天我们了解了RAG的相关知识

  1. 什么是RAG：检索增强生成，结合检索和生成的技术
  2. 为什么需要RAG：解决LLM的知识截止日期、幻觉问题、私有知识问题
  3. RAG的核心组件：文档加载器、文本分割器、嵌入模型、向量数据库、检索器、LLM
  4. RAG的高级技巧：查询转换、混合检索、重排序、多轮对话
  5. RAG的评估：检索评估、生成评估
  6. RAG的架构演进：Naive RAG → Advanced RAG → Modular RAG
