聊聊AI Agent（五）：LangGraph入门

2026-06-03 AI Agent系列 AI, Agent, LangGraph, 状态机 0 Comments Word Count: 2k(words) Read Count: 9(minutes)

前言

在前面的文章中，我们学习了LangChain的基础和高级特性。LangChain的Chain是线性的，但是现实世界中的AI应用往往需要更复杂的流程控制，比如条件分支、循环、并行执行等。LangGraph就是为了解决这个问题而诞生的。今天就来聊聊LangGraph是什么，以及如何使用它来构建复杂的AI工作流

什么是LangGraph

LangGraph是LangChain团队开发的一个库，它基于图（Graph）的概念来构建AI工作流

用通俗的话来说，LangGraph就是一个”流程图引擎”，它可以让我们用图的方式来定义AI应用的执行流程

为什么需要LangGraph

那么为什么需要LangGraph呢？我们来看看LangChain的Chain有什么局限性

LangChain Chain的局限性

LangGraph的优势

LangGraph的核心概念

1. State（状态）

State是LangGraph的核心概念，它定义了图中流转的数据结构

2. Node（节点）

节点是图中的处理单元，每个节点接收状态作为输入，返回更新后的状态

3. Edge（边）

边定义了节点之间的连接关系

4. Conditional Edge（条件边）

条件边根据状态决定下一步执行哪个节点

添加工具调用

让我们来构建一个可以调用工具的Agent

人工干预

LangGraph支持在某个节点暂停，等待人工确认

可视化

LangGraph可以将图可视化，方便我们理解和调试

LangGraph vs LangChain Chain

特性 LangChain Chain LangGraph
流程控制 线性 图结构（支持分支、循环）
状态管理 简单 强大（支持复杂状态）
人工干预 不支持 支持
并行执行 不支持 支持
可视化 不支持 支持
检查点 不支持 支持
适用场景 简单线性流程 复杂AI工作流

总结

今天我们学习了LangGraph的基本概念

  1. 什么是LangGraph：基于图结构的AI工作流引擎
  2. 为什么需要LangGraph：实现条件分支、循环、并行、人工干预
  3. LangGraph的核心概念：
    • State：状态定义
    • Node：处理单元
    • Edge：连接关系
    • Conditional Edge：条件分支
  4. 构建简单图：聊天机器人
  5. 添加工具调用：支持工具的Agent
  6. 人工干预：在关键节点暂停等待确认
  7. 可视化：将图可视化方便调试

LangGraph是构建复杂AI Agent的重要工具，在接下来的文章中，我们将学习LangGraph的高级特性和多Agent编排
